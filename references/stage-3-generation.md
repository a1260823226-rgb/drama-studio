# Stage 3 · AI 成片

目标：把验收过的分镜编译成**可直接投喂生成平台的切片 Prompt**，生成、验收、修复，直到成片。

## 1. 编译（compile-slices）

```bash
python {baseDir}/scripts/drama_studio.py compile-slices <项目>-storyboard.json \
  --assets <项目>-assets.json --scenes <项目>-scenes.json --out <项目>-slices.md
```

编译是确定性的：模板头、字段顺序、`@UUID` 绑定、台词逐字块，全部由脚本拼装，**模型不参与**。
门不过则拒绝编译（`--force` 可强行编译，仅用于调试）。

产物结构（`examples/三打白骨精-slices.md` 是完整样例）：

1. **拆解说明**：切分逻辑、断点序列、连续性序列、各切片台词字数。
2. **UUID 对照表**：本片用到的全部人物/场景。
3. **切片 Prompt**：每个切片一段代码块，头部注明源场次/断点/景别/运镜/连续性/台词字数。
4. **通用空白模板**：新剧本复用的空白模板（原文见 `assets/templates/slice-prompt.md`）。

单个切片 Prompt 的形态：

```text
真实电影风格。无BGM。无字幕。风格要求真实，镜头切换自然。
人物：@a9cf0873-e937-4657-8eb0-a2d7dd2f77c2是孙悟空。@f44f5bb2-4cbf-468e-be1f-fe8ddca78d0d是唐僧。@fc55e7ef-0539-4d24-b8e6-63ab5f0f008c是猪八戒。@9ddcf00e-bfb0-480b-8b86-25e914befbbe是沙僧。
场景：@3d1393e6-f6bd-4bac-8c7e-1c8a5ae6efb6是白虎岭古道。
景别：中景。
运镜：推镜。
镜头语言：中景平视，机位略低于马背缓推，唐僧与猴王分置画面左右，马颈作前景压住下缘，收在云影没入雾中。
画面内容：坡上停留处，唐僧扶鞍，悟空立于马侧，唐僧松开缰绳，按住腹部，抬眼看悟空；孙悟空收棒抱拳应命，转身一纵，脚踏云头翻过山脊；猪八戒把担子撂在地上，靠着石头坐下，沙僧持杖四望。
{唐僧（气息虚弱）：悟空，为师腹中饥饿，你去南山摘些桃子来。}
{孙悟空（抱拳）：师父稍等，弟子去去就回，八戒沙僧守好行李。}
```

编译纪律：

- **模板头逐字不可改，字段顺序不可动**；景别/运镜默认不加 `【】`（要加：`params.fieldBrackets = true`）。
- `@UUID` 是平台解析语法：**绝不改写成 `[UUID]` 或 `@孙悟空`**，错写会静默丢失绑定。
- **镜头语言**位于运镜与画面内容之间：景别层次/机位角度/运镜方式/构图/组接，一句话说清本切片的视觉意图（写法见 `stage-2-storyboard.md`）。
- 台词 `{}` 块逐字来自剧本；无台词切片不写 `{}` 块。
- 画面内容 = 环境铺垫 + 3-5 个动作单元，由 `actionUnits` 确定性拼装。
- 每条 Prompt 只描述本切片：不重演上一片已发生的动作，不提前泄漏后续剧情。

## 2. 生成前：预览-确认-失效

提交前输出可读预览：模型/入口、模式、时长、分辨率、音频、完整 prompt、参考文件及各自职责、预计费用、种子、候选与重试上限。

- 质量档 ≠ 付费授权：预算上限、上传范围、候选数、停止条件单独授权。
- 用户确认后，**任何改变画面或费用的字段变更都使确认失效**，要重新确认。
- 提交成功立即记录请求 ID；超时先查任务历史找回，**不盲目重提**（重复付费）。

## 3. 验收：四道门 + 证据

下载真实素材后，抽帧（开头 / 25% / 50% / 75% / 结尾）、慢放查接触峰值、有音频就转写人工听。

| 门 | 查什么 | P0 判定示例 |
|---|---|---|
| **剧情** | 冷观众（没读过梗概）能说出目标/阻碍/行动/结果；笑点有铺垫 | 笑点只能靠台词说"我的食物呢"、角色看见原因却按没看见表演 |
| **身份/画风** | 脸、身体、服装拓扑、材质跨切片不漂移 | 主角身份错误；服装拓扑变化且身份含混 |
| **物理/连续** | 接触有 接近→施力→响应→稳定结果；轴线、方向、道具状态可信 | 穿模、关键接触多肢体、车该倒车却前进 |
| **声音** | 说话人唯一、嘴型对上、声线一致、音乐不重启 | 工作人员台词由猫咪动嘴、多角色同步开口 |

- **任何 P0 不过 → 不得标 `accepted`，不得作为后续切片的父片段。**
- 证据分级：直接看过/听过 = 证据；用户转述 = "用户报告"；没检查 = "未验证"。不得把没检查的素材说成已通过。
- 文字类内容（手机 UI、信件、价签）默认后期叠加；生成出的关键文字变异 = 拒绝该画面，重做干净底板。

## 4. 修复：五判决 + 单变量

| 判决 | 条件 | 下一步 |
|---|---|---|
| **保留** | 主要目标已交付，无致命缺陷 | 锁定、记录、走人 |
| **后期修** | 缺陷在后期领域（色彩/字幕/混音/修剪/端部几帧） | 绝不为剪辑几分钟能修的烧 takes |
| **编辑而非重生** | 构图时机对，只错一层，入口支持 edit | 保留 take 为源片，只改失败层 |
| **换种子重抽** | prompt 对，采样不走运 | 同 prompt 新 seed，**最多 2-3 次**，之后就是 prompt 的问题 |
| **重写** | 同一缺陷出现在 ≥2 个候选 | 系统性失败：按机制诊断，改切片设计，不堆形容词 |

- **一次只改一个变量**：一个 prompt 子句、或种子、或模式、或一个参考。
- **尝试预算**：生成前写下最大候选/重试数与"足够好"标准；预算过半同一缺陷无进展 → 停止迭代，换策略（拆短、减角色、简化动作、换模式），不无限重抽。
- **最小修复**：纯声音断裂→重混；接缝失败→剪短/动作桥/插镜；后半段漂移→保留前段，重新锚定并缩短；身份/因果失败→重生最小单元。
- **"不生成"也是合法交付**：密集屏幕文字属于后期；真实产品精确行为属于摄影机；权利不清属于授权流程；两次失败后属于另一个想法。

## 5. 状态更新（每验收一片）

1. 把切片 `status` 改为 `accepted` / `repair` / `rejected`（`rejected` 不进 canon，不能当续拍源）。
2. 把**实际观察到的**结尾状态写回 `exitState`——实测覆盖计划；后续切片从实测状态继续。
3. 需要时调整下一片的 `entryState` / `continuity`，重跑 `validate-storyboard` 再重编译受影响的切片。
4. 提取验收尾帧（如 `duration - 0.2s` 处抽一帧，留安全余量）作为 chain 切片的下一片首帧参考。

## 6. 成片与交付

- 把各切片的**验收区间**（不是整条生成）装进时间线；生成时长 ≠ 入片时长。
- 分轨：对白 / 环境 / 音效 / 音乐；统一响度；J/L cut 桥接声音接缝。
- 字幕、封面、文字图层后期叠加；交付前跑技术门（分辨率、响度、时长、命名规范）。
- 命名：`项目_切片号_版本_画幅_状态`，如 `三打_S06_v2_9x16_accepted.mp4`。
